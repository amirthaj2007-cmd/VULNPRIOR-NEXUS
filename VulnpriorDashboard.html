Coverage and limitations

  • Only exact version pins are queried in this browser companion.
  • OSV matches are intelligence leads, not proof of exploitability or reachability.
  • A failed network request is marked as an error, never as a clean scan.
  • The Python application supports ZIP uploads and additional manifests including Poetry and Pipfile lock files.
  • This does not scan source code, secrets, runtime configuration, or every transitive dependency.

ENGINEERING TRANSPARENCY

Methodology & university demo guide

Use these notes to explain what the system does, how it ranks findings, and where its boundaries are.

Architecture

  • Data layer: local vulnerability records and organisation profiles.
  • Scoring layer: deterministic, profile-weighted CVSS + CISA KEV + EPSS prioritisation.
  • Repository layer: safe manifest parsing and OSV advisory lookups for exact package versions.
  • Presentation layer: browser demo for offline exploration and Python/Streamlit app for full scanning/report workflows.
  • Output layer: ranked findings, remediation guidance, CSV/JSON exports, and PDF report generation.

Live demo checklist

Viva questions — practice answers

Why combine CVSS, EPSS, and CISA KEV?

CVSS represents technical severity, EPSS estimates exploitation likelihood, and CISA KEV flags vulnerabilities known to have been exploited. They represent different signals, so the system combines them using organisation-specific weights.

Why can two organisations rank the same CVE differently?

The selected profile changes the scoring weights and in-scope critical products. A risk ranking should reflect the organisation's context rather than severity alone.

Does a high score mean compromise is certain?

No. The score is a deterministic prioritisation aid, not a calibrated probability of compromise. Exposure, affected version, reachability, and compensating controls still need validation.

What exactly does the repository scanner inspect?

It reads supported dependency manifests and queries OSV for exact package versions. It does not execute uploaded code and is not a full source-code, secrets, or runtime security audit.

What does “no matches returned” mean?

It means the queried exact versions returned no known matches from that lookup. It does not prove the repository is secure; coverage can be limited by unpinned dependencies, missing advisories, unsupported manifests, or network failures.

How would you evaluate this system?

Use labelled test cases, verify ranking determinism, measure top-k recall against a curated reference set, check parser coverage, and report OSV lookup failures separately from clean results.
